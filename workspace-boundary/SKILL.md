# 工作区边界

## 问题

不同 agent 对文件的处理差别很大：有的只在启动它的文件夹里读写；有的会读整台电脑，一次搜索就可能把桌面、下载、其他案件的材料翻出来。对律师来说，这不只是效率问题，是保密问题：读进上下文的东西就发给了模型服务。

还有一个问题是**文件在哪里不明确**：材料散在桌面、下载、微信文件夹里，agent 到处找，你也说不清它最后读了哪份。

## 两层边界

**提示词挡不住一个要去读文件的 agent。** 技能里写“不要读工作区以外的文件”，模型多数时候会照做，但这不是保证。真正的边界只能由平台的权限设置来设。所以分两层：

| 层 | 作用 | 由谁执行 |
|---|---|---|
| 平台层（硬） | 工作区以外的文件读不到、写不了 | 平台的权限与沙箱设置 |
| 技能层（软） | agent 知道该去哪里找、找不到就问、不去试探边界 | 本技能的工作规则 |

平台层是保证，技能层减少碰壁和误操作。两层都要。

## 一、先定工作区（一次）

**工作区是你指定的一个文件夹**，agent 在里面读写，其他地方一律不碰。

- 按“需要一起看的范围”定：一个案件一个工作区最严；所有案件放在一个“案件根目录”下、整个根目录作为工作区最方便（推荐，见“收件箱”）。
- 不要把家目录、桌面、文稿整个当作工作区，那等于没有边界。
- **绝不该被读到的东西不要放进工作区**，例如脱敏工具的私密区、原件、未脱敏稿。它们放在工作区以外，工作区里只放可以交给 AI 的材料。
- 工作区以外、但确实需要读的目录（例如脱敏工具的导出目录），作为**只读目录**单独加入。

## 二、平台层：把边界锁死

### Claude Code

在工作区运行一次（`$SKILL` 为本技能目录）：

```bash
python3 "$SKILL/scripts/setup_workspace.py" "<工作区>" --read "<只读目录>"
```

它在 `<工作区>/.claude/settings.json` 里合并写入：

| 设置 | 效果 |
|---|---|
| `permissions.blockReadsOutsideWorkingDirectories: true` | 读文件、搜索文件的工具（Read、Grep、Glob）只能读工作区和加入的目录，任何权限模式下都生效 |
| `permissions.additionalDirectories` | 加入只读目录和技能目录（技能自己的参考文件、脚本要能读到） |
| `sandbox.enabled: true` | shell 命令在沙箱里运行，写入只限工作区 |
| `sandbox.filesystem.denyRead: ["~/"]` ＋ `allowRead: [工作区, 只读目录, 技能目录]` | shell 命令读不到家目录下除这些以外的任何东西（上一项只管文件工具，不管 `cat` 这类命令，所以要这一项补上） |
| `sandbox.allowUnsandboxedCommands: false` | 不允许命令绕过沙箱 |

注意：

1. **以工作区为工作文件夹新开会话**，设置才生效；已经打开的会话不会自动套用。子代理继承同一会话的设置。
2. **第一次打开要接受“信任此文件夹”的提示。** 未信任的文件夹，项目设置里的 `additionalDirectories` 会被忽略，只读目录和技能目录就读不到了。
3. shell 沙箱只封住家目录（`~/`）以下的路径。工作区和材料都应放在家目录下；系统目录（如 `/usr`）保持可读，命令才能运行。
4. 检查是否到位：`python3 "$SKILL/scripts/check_workspace.py" "<工作区>"`，它也会检查可读范围里有没有“私密区”这类不该出现的目录。
5. **自测**：`python3 "$SKILL/scripts/selftest_workspace.py" "<某个位置>"` 搭一个三文件的测试环境，按它打印的话在新会话里试一次，确认工作区外的文件用文件工具和 shell 命令都读不到。

### 其他 agent 平台

先查平台文档，确认两件事：

1. 能不能把**文件读取**限制在工作目录内；
2. **shell 命令**有没有沙箱、能不能限制读取范围。

两样都有，就照上表的意思配置。缺一样的，平台层就不完整，这时用操作系统隔离：给 agent 单独开一个系统用户或容器，里面只放工作区；或者只把材料的**副本**放进一个专用文件夹给它用。不要以为“技能里写了就够了”。

## 三、技能层：agent 的工作规则

所有在工作区里干活的 agent，包括它派出的子代理，都按这几条做：

1. **开工先确认工作区。** 第一句说明本次工作区是哪个文件夹（和只读目录）。不知道的，问用户，不要自己猜一个。
2. **只在工作区里找。** 不在工作区以外搜索、不列目录、不 `find ~`、不用 `/` 或 `~` 开头的通配搜索。
3. **找不到文件就问，不要到处翻。** 用户说“那份合同”但工作区里没有，就问它在哪，或请用户放进收件箱。
4. **工作区外的文件，请用户放进收件箱。** 用户给了一个工作区以外的路径或附件，不去读原位置，请用户把它放进工作区的 `收件箱/`（平台层通常也会挡住读取，这是对的）。
5. **派子代理时写明可读路径。** 派单里列出它可以读的具体文件夹，其余一律不读。
6. **产出只写进工作区。** 草稿、记录、导出文件都放在工作区内约定的位置。
7. **被边界挡住时，报告，不绕过。** 读取被拒绝就告诉用户哪个文件被拒、为什么需要它，由用户决定是否把它放进收件箱或调整只读目录。不要换命令、换路径去试。

## 四、收件箱：不用每次选路径

推荐的工作区结构：

```
案件根目录/              ← 工作区（只设一次）
  .claude/settings.json  ← 边界设置
  收件箱/                 ← 新文件一律拖到这里
  甲诉乙买卖合同纠纷/     ← 每个案件一个文件夹，由 agent 建
  丙公司破产重整/
```

- 你只需要记住一个地方：**收件箱**。新材料（包括从脱敏工具导出的外发稿）拖进去，告诉 agent “这是某某案的材料”。
- agent 在案件根目录里找到这个案件的文件夹（没有就新建），把文件从收件箱移进去，登记来源和时间。
- 以后关于这个案件，说案件名就行，路径由 agent 管。

具体到案件，`legal-case-workbench` 已经按这个结构实现（建档、收件、找案件都有脚本）。

## 文件一览

```
$SKILL/
  SKILL.md
  scripts/
    setup_workspace.py     给工作区写入 Claude Code 边界设置（合并，不覆盖）
    check_workspace.py     检查边界是否到位、可读范围里有没有不该出现的目录
    selftest_workspace.py  搭三文件自测环境，确认边界真的生效
```
