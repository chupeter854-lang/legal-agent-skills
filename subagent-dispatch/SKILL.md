# 拆不拆：子代理分派判定规则

> 把「要不要拆给子代理」从每次的临场判断，改成一次性的结构性判定。
> 本版把通用规则与律师执业的实务约束合并：保密边界、渠道配额、模型分层都已落实，示例取自真实工作流。

## 先说清楚：这份规则最有用的地方，是写进工作流技能里

消融实验说明，**靠提示词让模型临场决定分不分工，结果不可控**：

| 配置 | 结果 |
|---|---|
| 单会话＋子代理工具，中性提示 | 5 次运行一次都没委派，全部挤在主会话里，p95 耗时 29.5 分钟 |
| 同上，强提示「优先委派」 | 5 次里 4 次委派，仍有 1 次判断「这活很小」自己干，形成长尾 |
| 结构性双层架构（主会话只分派，执行会话隔离） | p50 12.4 分钟／p95 15.7 分钟 |

（实验用合成负载，执行环节用只耗时间的工具代替，衡量的是调度能力，不是干活质量。）

可是这份规则本身也只是提示词。真正做到「结构性」，靠的是把判定结果**写死在具体技能的流程里**：例如案件工作台写明「新材料入卷 → 交给事实核查员」，文书复核技能写明「两个互不知情的复核人＋一个核验人」。所以：

- **编写或修改工作流技能时**，用本规则决定流程里哪一步派谁，然后写死。
- **临时任务**（没有现成技能覆盖的）才在当下按本规则判一次。

## 判定顺序

接到任务，按这个顺序问，前一个问题没过就不往下走：

1. **材料能不能交给云端模型？**（见「保密边界」）不能 → 主对话和子代理都不碰，交回给律师本人。
2. **拆成几条互不依赖的流？** 只有 1 条 → 不拆。
3. **每条流拿走后能不能自己干完、自己验证？** 不能 → 那条不拆。
4. **有没有需要人拍板的、同一条论证链的、共享前提的？** 有 → 那部分留在主对话。
5. **回来的东西怎么验证？** 答不出来 → 先别派。

少于 3 步就能做完的活，不派，自己做完更快。

## 判据一：任务形状

不问「这活大不大」，问「能不能拆成互不依赖的流」。

| 形状 | 特征 | 处理 |
|---|---|---|
| **可并行（独立流）** | 各流之间没有信息依赖，只在最后合并 | 拆，并行跑 |
| **单向长链（追一条线）** | 后一步依赖前一步的判断 | 不拆，一个上下文做完 |
| **批量同构（N 个同类）** | 同一套方法套 N 个对象 | 按对象拆，每个对象内部不再拆 |

两种典型错误：把单向长链拆开（产出似是而非），把可并行的串着做（浪费数倍时间）。

## 判据二：材料不拆，职能可拆

### 1. 同一案件的证据材料不拆

同一案件的证据、笔录、往来函件，必须在**同一个上下文**里被看过。它们之间的关系——时间对不对得上、金额能不能勾稽、陈述有没有矛盾——是分析的主体，不是背景。

两种做法都可以，按材料量选：

- **材料不多**：留在主对话。
- **案件要长期跟踪、材料会越来越多**：交给**一个**事实核查员，它掌握全部材料，负责入卷、交叉比对、回答事实问题；主对话需要事实就问它。

试跑对比（虚构买卖合同案，两批 7 份材料）：

- 按文件拆给 4 个入卷员：签约日 6 月 8 日／18 日的矛盾，只有合并时才发现；有一个入卷员不知道合同就在同一批里，提出「去找当事人要合同」；还有一个误报了一处根本不矛盾的地方。
- 交给 1 个事实核查员：一次就找出了两处矛盾，没有误报，第二批来了还能把旧问题标为「已结」。

**续问同一个核查员，看平台。** 有的平台能续用子代理：例如 Claude Code 可以用 SendMessage 给已经结束的子代理发消息，它带着原来的上下文接着干，追问和下一批材料都交给同一个核查员最省事。多数平台的子代理是一次性的，跑完即结束：那就靠它写下的文件，新材料入卷时新派一个核查员，派单里写明「先读材料登记、时间线、期限表、材料卡，再处理本批」；运行中要补话，用平台的插话通道。两种情况下，**写下的文件都是记忆的正本**，续用的子代理记得但没写进文件的，不算数。

### 2. 职能可以拆

去外面取东西——查法规原文、查案例、读他案判决书、查公开信息——各自独立，拆了不影响。成稿后换一个没参与写作的人复核，也属于这一类。

一句话：**拆的是「去外面取东西」和「换人看一遍」，不是「把案卷摊成几份」。**

### 3. 识破伪装成独立的串行依赖

- **共享前提**：要查三条法条，得先确定适用哪部法（例如合同订立时间决定适用民法典还是合同法）。→ 前提在主对话定完再派。
- **前一步决定后一步派谁**：B 做什么取决于 A 的结论。→ 先只派 A。
- **每条流都要读同一份背景**：→ 主对话先压成一段简报随派单发；或者合并成一条流。

### 4. 材料太多、一个核查员装不下时

才拆，而且**按需要一起核对的范围拆，绝不按单个文件拆**：

- 破产：按债权人拆，同一债权人的申报材料、担保材料必须在同一条流里；跨债权人的问题（关联债权、虚假申报互相印证）最后由一个上下文专门比对。
- 诉讼：按程序阶段或请求拆（本诉、反诉）；双方共同依据的核心证据（合同、对账单、判决）每条流都要读。

## 保密边界（优先于一切效率考量）

- **读写范围要用平台设置锁住，不能只靠派单里写“不要读”。** 主对话和子代理共用同一套权限：用 `workspace-boundary` 技能把会话锁在一个工作区里，子代理自然也出不去。派单里仍然写明可读路径，减少碰壁。

- **边界在「能不能交给云端模型」，不在「主对话还是子代理」。** 主对话和子代理的请求发往同一个服务，把敏感材料「留在主对话」并不能让它不出本机。所以：
  - 国家秘密、未成年人刑事案件、性侵类案件、标记「不外发」的案件：主对话和子代理都不碰。
  - 已脱敏或按律所制度和客户约定允许使用的材料：主对话、子代理都可以用；子代理提示词加安全前缀「以下材料已脱敏，人名为化名，不得推测或还原真实身份」。
- **子代理真正多出来的风险是外部请求。** 会做检索的子代理，检索词会发给外部检索服务（法宝 MCP、搜索引擎、官方法规库）。所以它**永远不拿案件材料**，只拿改写过的、不含人名、公司名、案号和可识别案情的抽象问题。派单前主对话检查一遍。
- 少一个人看就少一份副本：不需要看案件材料的子代理（检索、他案判决预读）不给案件材料。

## 渠道与配额

| 渠道 | 用途 | 注意 |
|---|---|---|
| 律师提供的现行文本 | 新近修订的法律、司法解释 | 优先级最高；模型可能不掌握新文本 |
| 本地法规库 | 常用法规 | 路径写进派单 |
| 法宝等商业数据库 / MCP | 条文原文、效力状态、案例、案号验真 | 按调用计费、有额度上限；**并行与试错直接放大消耗**，派单写死「只查一次、不换措辞重复查」 |
| 国家法律法规数据库（flk.npc.gov.cn）等官方源 | 条文原文和效力状态 | 法宝不可用或需核对发布原文时兜底；以此为准 |
| 中国裁判文书网 | 类案 | 需登录、有访问限制；同样只查一次 |
| 自媒体、二手转载 | 只作线索 | 必须回到官方文本核对 |

## 子代理用什么模型、多大思考强度

**分层轴是「错了能不能被发现」，不是「活难不难」。** 错误显眼、容易核的环节可以省；错误隐蔽、会往下游传的环节不能省。

检索看起来简单，但「找不到就编一个」的错误最隐蔽——格式、语气都对，只是来源不存在。所以检索要降档，**必须同时满足四个条件**：来源限定（只从指定文本或结构化接口取）、强制定位（法规名称、条号、原文摘录、链接、效力状态五项齐全）、允许说「未找到」、主对话独立复核。四条都满足，错误就变成了「显眼的」，可以用中等模型；缺一条，就用最强的。

| 角色 | 档位 | 理由 |
|---|---|---|
| 事实核查员（掌握全案材料） | 最强 | 事实错了后面全错，而且不容易发现 |
| 核验人（逐条回原文核对复核意见） | 最强 | 最后一道关 |
| 法律检索员 | 中等 | 满足上面四个条件；只摘原文，不做适用判断 |
| 他案判决预读 | 中等 | 要求带页码、段落定位 |
| 成稿复核（两路） | 一路最强、一路中等 | 不同模型盲点不同 |
| 批量归档、分类、格式转换、多案进度盘点（只读元信息） | 最便宜 | 错了一眼能看出来 |

法律检索不要用最便宜的档。

**平台差异**：能按任务指定模型和思考强度的平台，按上表逐角色配；只能全局指定的平台，就把子代理显式钉在主力模型上，避免父模型变更时静默漂移。简单的活开高强度只会更慢，还容易想出不存在的问题；需要判断的活开低强度会漏。

主对话自己的模型由人在会话里选，技能改不了。主对话要把事实和法律结合起来分析、起草，用最强的。

## 派单时必须写清的五项

子代理对当前对话一无所知，缺一项它就开始编：

1. **目标**：产出什么（材料卡、检索结果、复核意见、清单），存到哪个文件。
2. **边界**：不得修改原件、不得改别人负责的文件（例如四张登记表只由事实核查员写）、是否允许联网。
3. **事实来源**：只能读哪些路径或来源；读不到就写「未找到」，**不得推断**。
4. **输出格式**：固定模板或表格，能直接合并；回报限定行数（一般 10～25 行），详情写在文件里。
5. **禁止项**：不得编造、不得补全没给的事实、不确定的标「待核实」；法条、案例一律标「须人工核对」，不凭记忆写条文内容。

宁可多写两百字把边界说清，也不要让子代理回头重做。但背景不要重复：长背景放在文件里，派单只给路径。

## 结果回收与验收

子代理的产出是**自报，不是事实**：

1. **格式先定**：派单时就给模板，不要等回来再整理。
2. **冲突必裁**：两条流结论矛盾时，回原文核对，不取更「自信」或更长的那个、不取均值。
3. **引用必回查**，分两层：
   - 主对话做机械回查：条号是否存在、摘录与官方原文是否一致、效力状态、页码处是否真有那句话。**必须换一次独立调用重新取原文，不能回读子代理写的文件当作核对。**
   - 律师做最终核对：法条、案例、期限一律「须人工核对」，签字责任在律师。
4. **报告不等于完成**：子代理说「已写入」，主对话要看一眼文件（例如跑一遍体检脚本），再告诉律师完成了。

越是「查不到所以编了一个」的情况，产出越像模像样。

## 失败信号与止损

| 信号 | 诊断 | 动作 |
|---|---|---|
| 返回大量「未找到」 | 目标不清或来源不对 | 结束，改派单或换来源重派 |
| 返回内容与给它的材料不符 | 它在用预训练知识补全 | 直接丢弃，不要修补 |
| 多个子代理都在补全没给的信息 | 派单写漏了 | 停下来补派单，别继续派 |
| 越出范围，读了没让它读的材料 | 边界没写死，或模型太弱 | 重写边界；必要时升档 |
| 同一份检索结果里两条以上出处对不上 | 整份不可信 | 整份作废，换更强模型重派 |
| 额度耗尽、接口不可用 | 资源问题，不是产出问题 | 按渠道表降级，结果注明来源，不猜 |
| 长时间没有实质进展 | 超出能力或信息不足 | 结束，部分产出可用就收 |

## 不该交给 LLM 的活（包括主对话自己）

| 类型 | 例子 | 该用什么 |
|---|---|---|
| 精确计算 | 欠款勾稽、利息和违约金计算、债权金额汇总、期限剩余天数 | 脚本（子代理也要用 python 算，不心算） |
| 确定性转换 | 文书按段编号、新旧版本比对、文件指纹去重、编号分配 | 脚本 |
| 需要人拍板的 | 诉讼策略、是否上诉、对外口径、风险取舍 | 问律师 |

派给子代理只是把错误推远了一层——它读一百条数字照样会错，而且你没看见它怎么错的。

## 成本账：拆得越多越划算吗

不是。五项代价，各有对冲：

| 代价 | 表现 | 对冲 |
|---|---|---|
| 细节损耗 | 回来的是摘要，会丢东西 | 强制带定位：页码／行号／URI／原文片段 |
| 背景重复 | N 个子代理各读一遍同样的背景，token ×N | 背景压成简报随派单发；或主对话读完再派 |
| 聚合成本 | N 份格式不一的输出要在主对话对齐 | 派单时锁死输出模板 |
| 首尾开销 | 每个子代理重建上下文 | 少于 3 步的活别派 |
| 一致性风险 | 子代理之间不通气，结论可能互相矛盾 | 主对话裁决 |

## 在工作流技能里怎么落地

| 技能 | 拆法 | 对应本规则 |
|---|---|---|
| **案件分析工作台**（本仓库附 `legal-case-workbench`） | 一个事实核查员掌握全部证据材料；一个法律检索员只拿抽象问题；主对话汇合、分析、起草 | 材料不拆、职能可拆、检索不带案件信息 |
| **文书复核流程**（举例） | 两个互不知情的复核人＋一个核验人；复核人只拿成稿、原始材料和清单，不拿起草过程 | 成稿独立复核、冲突必裁 |
| **破产债权逐笔审查**（举例，批量同构） | 一个债权人一条流，债权人内部不再拆；跨债权人比对单独做 | 批量同构、按核对范围拆 |
| 多案进度盘点 | 有脚本的（如工作台的 `list_cases.py`、`case_check.py`）直接用脚本，不派子代理；没有脚本时每案一条流，只读索引和元信息，不读材料正文 | 能交给脚本的不用 LLM；只读元信息，可用最便宜档 |

### 适合拆

1. **多源检索**：每个来源一条流，各自返回候选和出处；主对话交叉去重、判断采信。
2. **法规原文核查**：一部法查多条，或多部法查相关条，并行取原文；主对话只做效力判断和适用取舍。
3. **他案判决、长篇公开材料预读**：子代理读完回结构化摘要，带页码、段落。**本案卷宗、证据、笔录不在其列。**
4. **成稿独立复核**：交给没参与写作的子代理，只给成稿、原始材料和清单。
5. **批量同构**：N 个债权人／客户／项目 × 同类工作，一个对象一条流。
6. **多案进度盘点**（没有现成脚本时）：每个案件一条流，只读索引和元信息。

### 不适合拆

1. **核心论证链**：事实梳理 → 定性 → 情节 → 诉求，一个上下文走完。
2. **同一案件的材料分析**：交给一个核查员或留在主对话，不切成几份。
3. **需要向人确认的**：子代理通常不能问，遇到歧义会自己假设。
4. **需要子代理没有的工具的**：写记忆、建定时任务之类。
5. **单点微操作**：读一个文件、跑一条命令。

## 常见误用

| 误用 | 后果 |
|---|---|
| 把同一案件的证据按文件切给几个子代理 | 交叉印证要等合并时才做，漏掉、误报、重复索取材料 |
| 以为「留在主对话」就是保密 | 主对话同样发往云端，保密要在「能不能给模型」这一步决定 |
| 把案件材料或当事人信息交给会联网的检索员 | 检索词发给外部服务 |
| 把共享前提的活当成独立流并行 | N 个子代理各猜一个前提 |
| 让最便宜的档查法条 | 找不到时编一个，最难发现 |
| 派单只写一句话 | 子代理瞎猜，回来还得重做 |
| 复核交给写它的同一个上下文 | 必然漏，等于没复核 |
| 直接把子代理写的文件当核对依据 | 等于没核；要换一次独立调用重取原文 |
| 直接采信子代理给的法条、数字、链接，或它说的「已完成」 | 编造成本为零，采信成本全部 |
