# 案件分析工作台使用说明

技能名称：`legal-case-workbench`（v0.6）
安装：把整个 `legal-case-workbench/` 文件夹放进你的 agent 技能目录即装好（各平台路径不同，通常是 `~/.<agent>/skills/`）。也可以临时放在任意目录，指示 AI「按 legal-case-workbench 的 SKILL.md 操作」。
原名“案件跟踪”（legal-case-tracker），2026-11-01 改为现名：功能已从长期跟踪扩展到事实核查、法律检索、分析和起草。
思路来源：DeepSeek Harness 团队《Super-agent 设计探索》（2026-10-31），只取本地可用的部分，去掉了云端常驻。拆法依据：同仓库的 [`subagent-dispatch`](../subagent-dispatch/SKILL.md)（子代理分派规则）。

## 一、解决什么问题

案件要跟几个月甚至几年，材料不断进来。全塞在一个对话里，上下文很快就满了；换个新对话，之前的东西又得重新讲一遍。

这个技能的做法：

1. **案件的记忆存在文件夹里，不存在对话里。** 每个案件一个工作台文件夹：一页“案件索引”，加上材料登记、时间线、期限表、待办与争点、议题、材料卡。新开对话说“打开某某案”，读完索引就能接着干。
2. **证据材料不拆开，按专业分工。** 只有三个角色：
   - **事实核查员**（一个）：掌握全案证据材料，整批入卷、交叉比对、回答事实问题。平台能续用子代理的（如 Claude Code），同一次工作里的追问都接着问它，它记得读过的材料；不能续用的，新派一个从案卷文件重建。
   - **法律检索员**（一个）：只拿去掉当事人信息的法律问题，查法规、司法解释、案例，给出原文、条号和出处。
   - **主对话**：和你沟通，把事实和法律结合起来分析、起草，维护索引和议题。它不通读原始材料，所以不会被材料撑爆。
3. **所有东西都有编号，顺着编号找回来。** 材料 M、时间线事件 E、期限 D、待办·争点·矛盾·待核实 Q、议题 T，每句话都能追到哪份材料第几页。
4. **子代理的回报先验收再采信。** 核查员说“已写入”，主对话跑体检脚本、按编号核对；检索员给的法条，主对话先回查官方原文，再交你核对。

## 二、怎么启动

**它不会自己开新对话。** 对话由你开；读材料、查法条的活，它在当前对话里派子代理去做。子代理在后台运行，做完把结果交回这个对话，不会作为新会话出现在侧边栏，也不需要你去操作。

**第一次：建工作台**

0. **只做一次：定案件根目录。** 选一个专用文件夹（例如 `~/案件工作区`，不要用桌面、下载或整个文稿），用 [`workspace-boundary`](../workspace-boundary/SKILL.md) 的脚本设好读写边界：`python3 workspace-boundary/scripts/setup_workspace.py ~/案件工作区`。私密材料、原件不放进去。
1. 新建一个对话（Claude Code 桌面 App 的 Code 标签页、终端里的 `claude`，或你所用 agent 平台的新会话），**工作文件夹选案件根目录**。第一次打开要接受信任提示。
2. 说“给徐某某买卖合同纠纷建个档”或“这是徐某某买卖合同纠纷的材料”。它会在根目录里找这个案件，没有就新建一个固定文件夹，名字是“当事人简称＋案由＋案件_建立日期”，例如 `徐某某买卖合同纠纷案件_20261101`，然后告诉你把文件拖进该文件夹的 `材料/`。你不用起名，也不用选路径。说出“建立案件工作台”“打开某某案”“新材料到了”这类话，技能会自动启用；没有反应时，在 Claude Code 里输入 `/legal-case-workbench` 直接调用。
3. 它先确认材料能否交给 AI，再问案号、程序阶段、当事人称谓，建好文件夹和第一个议题。
4. 以后这个案件的新材料都拖进同一个 `材料/`，说“徐某某的案子新材料到了”。

**以后：接着干**

- 同一天、同一个对话里可以一直往下做：追问事实、加材料、查法条、起草。
- 第二天，或对话已经很长时，**新开一个对话**，说“打开某某案”。它先体检、读一页案件索引，几行字告诉你进度和临近的期限，然后接着干。之前聊过的内容不用重讲，都在案卷文件里。
- 想看所有案件，说“盘点一下手上的案件”。

**两条习惯**

- 一个对话只办一个案件（多案盘点除外），多个案件混在一起上下文会互相干扰。
- 想先熟悉流程，说“用案件分析工作台自带的示例案件试跑一下”，示例在本技能的 `examples/虚构买卖合同案/`，全部虚构。

## 三、日常怎么用

| 你说 | 它做 |
|---|---|
| “给某某案建立案件工作台” | 建文件夹，问你案号、阶段、当事人称谓，建好第一个议题 |
| 把新材料放进 `材料/`，说“新材料到了” | 脚本找出新文件、分配编号；事实核查员整批读完、和已有材料交叉比对、写进各表；主对话验收后更新索引，向你汇报新期限和矛盾 |
| “打开某某案”／“继续跟进某某案” | 先体检（期限还剩几天、未入卷的材料、超过 30 天没结的事项），再用几行字告诉你现状 |
| “盘点一下手上的案件” | 每个案件跑体检脚本、只读索引，汇成一张表 |
| “这个案子里……当时是怎么说的” | 问事实核查员，答案每句都带出处 |
| “查一下……的规定” | 主对话先定前提、去掉当事人信息，派法律检索员，用法宝 MCP 查法规与案例；主对话再用同一工具独立复核一遍，结果交你 |
| “起草一份……”“分析一下……” | 主对话结合事实和法条起草，放在 `草稿/` |
| “案件体检” | 脚本检查，必要时请核查员做一次全案事实体检 |

**脱敏要你自己做**：材料放进 `材料/` 之前完成脱敏，本技能不提供脱敏工具，也不判断脱敏是否充分。国家秘密、未成年人刑事、性侵类案件，以及按你的保密规则不允许外发的案件，不建档。

## 四、模型与思考强度

| 角色 | 模型 | 思考强度 | 为什么 |
|---|---|---|---|
| 事实核查员 | 跟随主对话 | 高 | 掌握全部证据，事实错了后面全错，而且不容易发现 |
| 法律检索员 | sonnet | 中 | 只摘原文；法宝 MCP 返回结构化原文＋法宝链接＋时效，来源限定、强制带出处、允许说“未找到”、主对话独立复核，四道约束下才降档；不用 haiku |
| 主对话 | 你在会话里选 | 你在会话里选 | 要结合事实和法律分析、起草，建议最强模型 |

原则：错误显眼、容易核的环节可以省；错误隐蔽、会往下游传的环节不能省。每个案件可以在 `工作台设置.json` 里改。

## 五、保密

- 关口在「这份材料能不能交给 AI」。主对话和子代理发往同一个服务，留在主对话不等于保密。
- 法律检索员会调用外部服务，检索词会发给北大法宝 MCP（降级时发给官方法规库），所以它永远不拿案件材料。

## 六、它不做什么

- 不替你决定期限。AI 推算的期限一律标“须人工核对”，你核对后改成“已核对”。
- 不判断法条真假，也不替你判断能否适用。主对话只做机械复核（用同一工具重取一次原文、逐字比对条号与摘录、核案号真伪），法条和案例由你最终核对。
- 不把 AI 的看法当成你的立场。议题里“当前立场”只写你确认过的。
- 不在后台常驻，不对外发送任何东西。草稿只存在本地。

## 七、版本与试跑（2026-11-01，虚构买卖合同案，两批 7 份材料，见本技能 `examples/虚构买卖合同案/`）

- **v0.1 按文件拆**：每份材料一个入卷员并行，再合并。问题：同批材料之间的矛盾只能合并时才发现；有入卷员不知道合同就在同一批里，提出“去找当事人要合同”；haiku 入卷员越权读其他材料并误报矛盾；四个入卷员各提一个新议题。
- **v0.2 按专业分工**：一个事实核查员整批入卷，第一批一次就找出签约日、违约金起算日两处矛盾，没有误报；第二批由同一个核查员接着处理，正确把旧问题标为已结，上诉期按送达回证推算到 11 月 7 日（星期六）并提示顺延待核。
- **v0.3 对照分派规则补齐**：保密关口的表述；核查员回报先验收；检索前先定共享前提；检索结果主对话回查；检索员边界和配额约束；失败与止损；多案盘点。

**v0.4 法律检索改为法宝 MCP**：`法律检索员提示词.md`（检索流程与工具选择）、`法宝检索与复核规范.md`（复核粒度、额度预算、降级顺序、常见错法）为新写；SKILL.md 第五节同步改为「同一工具独立复核」。尚未试跑。法宝 MCP 由律师本人配置、密钥不进技能；额度按账户计，开查前须确认。

**v0.5 落地修正**：
- 续用子代理按平台区分：能续用的（Claude Code 的 SendMessage）接着交给同一个核查员；一次性的新派并先读案卷。案卷文件是记忆的正本。
- 额度由主对话向律师确认后，作为 `{本次调用上限}` 写进派单；检索员不自己查余额，用到上限即停。问题标“关键”的优先查。
- 注明法宝工具在 Claude Code 里的实际名字形如 `mcp__<连接器名>__get_law_item_content`。
- 新增本地配置层：`references/本地配置.md`（不进仓库，示例见 `本地配置.示例.md`），放使用者自己的保密规则、材料目录约定、衔接技能；与 SKILL.md 冲突的以它为准。
- `init_case.py` 新增 `--materials-dir`：材料放在别处（如脱敏工具的导出目录）时直接指过去，只读不动。
- 新增虚构示例案件。

**v0.6**：案件根目录＋每案一个固定文件夹。`init_case.py --root --party --cause` 在根目录下建“当事人简称＋案由＋案件_建立日期”文件夹，发现同一当事人、同一案由的旧文件夹会先停下确认；`list_cases.py` 按当事人简称、案由、名称、代号、案号找案件。读写边界交给新技能 `workspace-boundary`。

**v0.5.1**：示例案件移入技能文件夹（`legal-case-workbench/examples/`），随技能一起安装，不再因为只复制技能目录而丢失；README 新增“怎么启动”。

还没试过：真实（脱敏）案件、PDF 扫描件、几十份材料的大批量、破产案件按债权人分议题、跨几周反复打开同一个案件、材料多到要拆分核查员的情形。
