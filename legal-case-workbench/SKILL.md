# 案件分析工作台

思路来自 DeepSeek Harness 团队《Super-agent 设计探索》（2026-10-31），去掉了云端常驻，并按律师工作的特点调整了分工。

## 设计原则

- **案卷是记忆，对话不是。** 案件的全部状态存在文件夹里。新开对话读完 `案件索引.md` 就能接着干。
- **证据材料不拆开分析。** 事实要放在一起才能核实：签约日两份材料说法不一、对账金额和判决认定差了一笔付款，这些只有同时看到全部材料的人才发现得了。所以全部证据材料交给**一个**事实核查员，它整批阅读、交叉比对；平台能续用子代理的，本次工作中的事实追问都接着问它。
- **按专业分工，不按文件分工。** 只分三个角色：
  - **事实核查员**：掌握全部证据材料，入卷、比对、核实、回答事实问题。四张登记表和材料卡只由它写。
  - **法律检索员**：只拿去掉当事人信息的法律问题，查法律法规、司法解释和案例，给出原文和出处。
  - **主对话**：和律师沟通，把事实和法律结合起来分析、起草，维护案件索引和议题。主对话不通读原始材料，需要事实就问事实核查员，需要法条就派法律检索员。
- **只有一个核查员装不下时才拆，而且按需要一起核对的范围拆。** 见“材料太多时”一节。
- **机器能确定的交给程序。** 登记新材料、分配材料编号、计算期限剩余天数、检查悬空编号，都用脚本。
- **子代理的回报是自报，不是事实。** 核查员说“已写入”，主对话跑一遍体检脚本确认；检索员给的法条，主对话先回查官方原文，再交律师核对。

拆法依据：`subagent-dispatch` 技能（子代理分派规则）。改本技能的分工前先对照它。

本技能目录记为 `$SKILL`，案件的工作台文件夹记为 `$CASE`。

## 模型与思考强度

从 `$CASE/工作台设置.json` 的“模型”“思考强度”读取，分别传给 Agent 工具的 `model` 和 `effort`；写“跟随主对话”的不传 `model`。默认：

| 角色 | 模型 | 思考强度 | 理由 |
|---|---|---|---|
| 事实核查员 | 跟随主对话 | high | 它掌握全部证据，事实错了后面全错，而且不容易发现 |
| 法律检索员 | sonnet | medium | 只检索和摘录，不做适用判断。检索“找不到就编一个”的错误最隐蔽，能降到 sonnet 是因为同时满足四个条件：来源限定（法宝 MCP 返回结构化原文，不靠抓网页）、强制定位（法宝链接＋条号＋原文摘录＋时效四项齐全）、允许写“未找到”、主对话用同一工具独立复核。缺一条就改用最强模型；不用 haiku |

主对话自己的模型和思考强度由律师在会话里选，技能改不了；它要结合事实和法律做分析、起草，建议用最强的模型。

## 第0步：保密确认

**先看有没有本地配置。** `$SKILL/references/本地配置.md` 存在的，先读它：里面是使用者自己的保密规则、脱敏流程、材料目录约定和要衔接的其他技能，**与本节冲突的以本地配置为准**。这个文件不进公开仓库（已写入 `.gitignore`），格式见同目录 `本地配置.示例.md`。

开始读任何材料前，用一句话确认材料是否已脱敏，或按律所制度和客户约定允许交给 AI 处理（本次请求里已说明的不再问）。

**本技能不内置保密规范。** 部署前把你的保密与脱敏要求（哪些案件不建档、脱敏标准、外发审批流程）写进 `references/本地配置.md`（或发给 AI，让它照示例写），并让事实核查员的 `{安全前缀}` 与之一致。

**保密的关口在这一步，不在“主对话还是子代理”。** 主对话和子代理的请求发往同一个服务，把材料留在主对话并不能让它不出本机。能交给 AI 的，主对话和事实核查员都可以用；不能交的，两者都不碰。

- 国家秘密、未成年人刑事案件、性侵类案件：不建案件工作台，告诉律师改用本机人工管理。
- 按你的保密规则不允许交给外部的案件：不建档，也不要把材料放进 `材料/`。
- **脱敏是你自己的步骤。** 材料放进 `材料/` 之前自己完成脱敏；完成后把 `工作台设置.json` 的“已脱敏”设为 true，事实核查员提示词的 `{安全前缀}` 替换为：“以下材料已脱敏，人名为化名，不得推测或还原真实身份。”未脱敏的替换为空。**本技能不提供脱敏工具，也不判断脱敏是否充分。**
- 子代理真正多出来的风险是外部请求：法律检索员的检索词会发给北大法宝 MCP 服务（降级时发给官方法规库），所以它**永远不拿案件材料**，只拿抽象的法律问题。主对话派活前检查问题里没有人名、公司名、案号和可识别的案情细节（年份、省份这类判断适用法律所需的粗粒度信息可以保留）。

## 第0.5步：工作区与收件箱（一次设好，以后不选路径）

**工作区是律师指定的一个“案件根目录”**，所有案件工作台都建在它下面，新文件一律经它里面的 `收件箱/` 进来。律师只需要记住收件箱，路径由你管。

```
案件根目录/              ← 本次会话的工作文件夹
  .claude/settings.json  ← 读写边界（见 workspace-boundary 技能）
  收件箱/                 ← 新材料拖到这里
  <案件名称>/             ← 每个案件一个工作台，由你建
```

- 案件根目录写在 `本地配置.md` 的“案件根目录”。没有写的，第一次使用时问律师一次，建议家目录下的一个专用文件夹（不要用桌面、下载或整个文稿），建好 `收件箱/`，写回本地配置。
- 读写边界用 `workspace-boundary` 技能的 `setup_workspace.py` 对案件根目录设一次（只读目录、技能目录它会一起加入），之后**以案件根目录为工作文件夹开会话**。第一次打开要接受信任提示。
- 绝不该被读到的东西（脱敏工具的私密区、原件、未脱敏稿）**不放进案件根目录**。脱敏工具导出的外发稿，拖进收件箱。
- 工作规则：只在案件根目录里找文件；找不到就问律师或请他放进收件箱；律师给了根目录以外的路径或附件，不去读原位置，请他放进收件箱；被权限挡住时报告，不绕过。

## 一、建立案件工作台（每个案件一次）

```bash
# 默认：在案件根目录下按案件名称建文件夹，律师不用选路径
python3 "$SKILL/scripts/init_case.py" --root "<案件根目录>" --name "<案件名称>" --type 民事
# 指定文件夹建
python3 "$SKILL/scripts/init_case.py" "<案件文件夹>" --name "<案件名称>" --type 民事
# 材料放在别处的（例如脱敏工具的导出目录），用 --materials-dir 指过去；该目录只读，不移动、不改动
python3 "$SKILL/scripts/init_case.py" "<案件文件夹>" --name "<案件名称>" --materials-dir "<材料所在目录>"
```

然后问律师（一次问完，答不上来的先空着）：案号、程序阶段、委托人与我方地位、当事人与统一称谓。写进索引“概况”和“当事人与称谓”，并按程序阶段建第一个议题（模板 `references/模板/议题.md`，例如“T-001 一审”；破产案件按债权人建）。

律师有常用的法规文本文件夹的，填进 `工作台设置.json` 的“法规库路径”。

## 收件：律师把文件交给你

律师说“这是某某案的材料”“把收件箱里的东西归到某某案”：

1. 找案件：`python3 "$SKILL/scripts/list_cases.py" "<案件根目录>" "<关键词>"`（名称、代号、案号都能搜）。找到唯一一个就用它；有几个就列出来问律师；没有就问律师是不是新案件，是的话按“一”在根目录下建。
2. 归档：`python3 "$SKILL/scripts/file_inbox.py" "<案件根目录>/收件箱" "$CASE"`（只归其中几份的，在后面写文件名）。文件从收件箱移进该案的 `材料/`，同名不覆盖，收件记录写进 `工作记录/收件记录.md`。
3. 接着走“三、新材料入卷”。
4. 收件箱里的文件分不清属于哪个案件的，列出来问律师，不要猜。

## 二、打开案件（每次新对话、或律师说“继续跟进某某案”）

律师只说案件名的，先用 `list_cases.py` 在案件根目录里找到文件夹。

```bash
python3 "$SKILL/scripts/case_check.py" "$CASE"
```

再读 `$CASE/案件索引.md`。用不超过 8 行向律师汇报：程序阶段；7 日内期限和已过期期限（逐条）；尚未人工核对的期限数；有没有未入卷的新材料；最要紧的两三条未结事项。然后等律师指示。

**多案盘点**（律师说“盘点一下手上的案件”）：先 `list_cases.py "<案件根目录>"` 列出全部案件，对每个工作台文件夹跑 `case_check.py`，再只读各案索引的“概况”和“近 30 日期限”，汇成一张表（案件｜阶段｜7 日内期限｜未核对期限数｜未入卷材料｜最要紧的一条）。全程不读材料正文，不派子代理。

## 三、新材料入卷

1. 登记，分配编号：`python3 "$SKILL/scripts/scan_materials.py" "$CASE" --register`。没有新材料就告诉律师。
2. **派事实核查员**（`references/事实核查员提示词.md`），`{任务}` 写“入卷：本批待入卷材料为 M-xxx～M-yyy”。
   - **平台能续用子代理的**（例如 Claude Code：用 SendMessage 给已经结束的子代理发消息，它会带着原来的上下文接着干）：本次对话里已经派过核查员的，接着交给同一个核查员，不另开新的，它记得已经读过的材料。
   - **平台的子代理是一次性的，或者这是新对话**：新派一个。提示词已要求它先读材料登记、时间线、期限表、待办与争点和已有材料卡，按需回看原件，重建对案件的认识，再处理本批。
   - 无论哪种，**案卷文件才是记忆的正本**：续用的核查员记得的东西，也必须已经写进各表；没写进表里的不算数。
3. **先验收再采信。** 跑 `case_check.py`，确认：待入卷为 0；没有悬空编号；回报里列出的新期限、矛盾编号在各表里确实存在（用 grep 按编号查）。对不上的，把差异发给核查员让它更正，不要自己改表。
4. 验收通过后，主对话：
   - 更新相关议题的“进展记录”“关联材料／期限”，以及索引的“议题”“近 30 日期限”“未结事项”“最近变动”“最后更新”。
   - 有新议题的（新的程序阶段、反诉、新债权人等），主对话新建议题文件并通知核查员把相关材料归过去。
5. 向律师汇报（不超过 12 行）：每份材料一行；**新增期限逐条列出并提醒须人工核对**；**矛盾逐条列出**；本批材料解决了哪些旧问题；核查员提出的需检索的法律问题（问律师要不要查）。

## 四、事实问题

律师问“之前……是怎么说的”“某某金额在哪份材料里”“对方这个说法有没有证据”：

- 索引里就有答案的，直接回答并注明编号。
- 其余交给事实核查员（能续用的接着问同一个；不能续用或新对话的，新派一个，`{任务}` 写“核实与回答：<问题>”）。把回答转述给律师，保留出处。

## 五、法律问题

**先合一笔额度账，额度由主对话向律师确认。** 法宝按调用计费、有额度上限，检索一次、复核一次各算一次调用。子代理不能向律师提问，平台也不一定有查余额的工具，所以：开查前主对话问律师当日可用额度，按“关键条文数 × 2”估算，把**检索员本次最多能用的调用次数**写进派单的 `{本次调用上限}`，复核要用的次数留给主对话自己。额度不够时按 `references/法宝检索与复核规范.md` 第五节降级，优先保证要写进文书的条文，其余标“因额度限制未检索”，不猜。

**工具名。** 本技能写的是法宝工具的短名（如 `get_law_item_content`）。实际名字因平台而异：Claude Code 里形如 `mcp__<连接器名>__get_law_item_content`，连接器名以你的配置为准。找不到时先列出可用工具确认名字，不要猜。

1. **先定前提，再派。** 问题来自律师，或来自核查员回报里的“需检索的法律问题”。适用哪部法、哪个时间段的文本（例如合同订立在民法典施行前还是后）这类共享前提，主对话先向核查员问清事实、定下来，写进问题里；定不下来的，在问题里写明“前提未定，请分别列出”。
2. **派一个检索员，不按问题拆。** 主对话改写成不含当事人信息的抽象表述，把要写进文书的问题标上“关键”，几个问题一起派给**一个**法律检索员（`references/法律检索员提示词.md`），不按问题拆成几个检索员——同一批问题共享前提和额度，拆开既费额度又容易各查一版。
3. **主对话复核（机械核对，不做适用判断）。** 按 `references/法宝检索与复核规范.md` 执行：
   - 要写进文书的每一条法条，用 `get_law_item_content` 以**法律名称＋条号**重新取一次原文，与检索员给的摘录逐字比对，同时核对时效字段；
   - 案例用 `anhao_recognition` 确认案号真实存在、对应哪份文书；
   - **必须换一次独立调用，不能回读检索员写的文件当作核对**；
   - 结果追加在检索文件末尾“主对话回查”一节，逐条写“已回查一致／不一致（差异）／无法回查”。
   - 不一致的那一条作废，不修补、不取中间表述；同一份结果里出现两条以上不一致的，整份作废，重派检索员并考虑换更强模型。
4. 检索结果存在 `$CASE/法律检索/`，主对话在议题进展里记一行并注明文件名。
5. 向律师汇报时，法条、案例一律标“须人工核对”，并说明回查情况（已核几条、作废几条、因额度未核几条）；检索员没找到原文的，主对话不得凭记忆补写条文内容。

## 六、分析与起草（主对话做）

- 主对话把核查员的事实（带出处）和检索员的法条（带出处）结合起来，在 `$CASE/草稿/` 写分析或文书初稿，文件开头注明“草稿，未经律师审核”。
- 起草中需要某个事实的原文表述、页码，问核查员，不要自己去翻原始材料。
- 只有律师确认过的立场才写进议题“当前立场”和索引“概况”；AI 的推断写进“AI 提示”。
- 有专门技能的交给专门技能（`本地配置.md` 写了对应技能的，按它衔接）：
  - **文书定稿后复核** → 交给一个独立的复核流程：两个互不知情的复核人＋一个核验人，复核人只拿成稿、原始材料和核对清单，不拿起草过程。先从索引和各表导出一份案件档案卡，存为 `$CASE/案件档案卡.md`，作为复核输入。
  - **破产债权逐笔审查** → 按债权人逐笔审，结论回写到对应债权人的议题。本仓库不含该流程，用你自己的。
  - **期限一览、开庭排期** → 用你自己的日历或期限管理工具；本技能的期限表只做记录和提醒，不做排期。

## 七、案件体检

律师说“案件体检”，或打开案件时脚本报出异常：

1. 跑 `case_check.py`，结果存到 `$CASE/工作记录/<日期>_体检.md`。
2. 需要读懂内容才能查的问题（时间线内部矛盾、材料卡里写了但期限表没有的期限、议题立场与后来材料冲突），交给事实核查员，`{任务}` 写“核实与回答：请对全案做一次事实体检，范围是……”。
3. 汇报问题，律师同意后再修改。

## 八、材料太多时

一个核查员能掌握的材料有限。出现下面情况再拆：

- 一次入卷的材料超过约 300 页，或累计材料多到核查员读不完相关原件；
- 破产案件债权人很多。

拆的原则：**按需要一起核对的范围拆，绝不按单个文件拆。**

- 破产：按债权人拆，每个核查员负责若干债权人的全部材料；同一债权人的材料、担保材料必须在同一个核查员手里。跨债权人的问题（关联债权、虚假申报互相印证）由主对话汇总后交给一个核查员专门比对。
- 诉讼：按程序阶段或请求拆（例如本诉一个、反诉一个），与该部分有关的证据全部给同一个核查员；双方共同依据的核心证据（合同、对账单、判决）每个核查员都要读。
- 拆分时四张登记表仍只能有一个写入者：各核查员先把结果写进 `工作记录/<日期>_<范围>_入卷结果.md`，最后由一个核查员统一写入各表，并做跨范围的交叉比对。

## 九、失败与止损

| 信号 | 动作 |
|---|---|
| 核查员回报与各表对不上 | 把差异发给它更正；第二次仍对不上，结束它，新派一个从案卷重建 |
| 核查员的回答与原件不符，或出处页码处没有那句话 | 丢弃这个回答，不修补；让它回原件重查，仍不符就换新核查员 |
| 核查员越出派单范围、读了没让它读的目录，或改了 `案件索引.md` 和议题 | 立即停止，告诉律师，按你所在律所的误发处理办法评估 |
| 检索员返回大量“未找到” | 问题写得不清或来源不对：改写问题或补充来源（例如请律师提供现行文本）后重派 |
| 检索员说额度不够、或查到一半额度耗尽 | 按《法宝检索与复核规范》第五节降级：只查要写进文书的条文，其余标“因额度限制未检索”，不猜 |
| 法宝 MCP 不可用（服务故障、密钥失效） | 降级到官方法规库，结果注明“未经法宝核验，来源为官方数据库”；密钥问题由律师本人处理，主对话不代填 |
| 检索员给的出处不存在、摘录与原文不符 | 该条作废；同一份结果里这类问题超过两条的，整份作废，改用最强模型重派 |
| 子代理长时间没有实质进展 | 结束它，部分产出可用就收 |

## 十、压缩索引

索引超过上限（默认 150 行）时：“最近变动”只留 10 行，“未结事项”只留 10 条；已结的议题在“议题”表里合并成一行；议题进展记录超过 30 条的，把较早的合并成“前期经过”（改前告诉律师）。不删除任何编号条目。

## 适用与不适用

适合：材料陆续进来、要跟几个月甚至几年的案件，例如一审到二审再到执行的民商事案件、刑事案件从侦查到审判、破产案件。

不适合：一次性的短任务（直接做更快）；不外发、不能交给 AI 的案件；需要实时监听群聊或邮件的场景（本技能由律师发起，不在后台常驻）。

## 试跑示例

律师说“用示例案件试跑”时：`$SKILL/examples/虚构买卖合同案/` 是全部虚构的买卖合同案件（两批 7 份材料，说明见同目录 README）。在律师指定的文件夹建工作台（**不要建在 `$SKILL` 里面**），先把 `第一批/` 复制进材料目录走“三、新材料入卷”，向律师汇报后再放 `第二批/`。材料是虚构的，第 0 步保密确认可以跳过，但要告诉律师跳过了。
