# 法宝检索与复核规范

给主对话用的操作说明：法律检索员交回结果后，怎么核、核到什么程度、额度怎么算。

## 一、为什么必须再查一次

检索员给的是**自报**，不是事实。它会看错条号、把相近条文的内容记混、把已废止的版本当成现行文本，也可能在没查到的情况下写出一段看着很像的条文。

所以复核不是"抽查一下显得严谨"，是**换一次独立的调用重新取原文，逐字比对**。两次取到的内容不一致，说明至少有一次是错的，那一条直接作废——不要去判断哪次对，重查第三次。

## 二、复核什么

| 项 | 怎么核 | 用的工具 |
|---|---|---|
| 法条原文 | 用法律名称 + 条号重新取一次，与检索员的摘录逐字比对 | `get_law_item_content` |
| 条号是否存在 | 取得到就是存在；取不到说明条号错了或法名错了 | 同上 |
| 效力状态 | 看返回的时效字段，与检索员写的是否一致 | 同上 |
| 案例 | 案号交给工具确认真实存在、对应哪份文书 | `anhao_recognition` |
| 类案内容 | 核对案由、审理法院、裁判日期与检索员写的是否一致 | `search_case` |

## 三、核到什么程度

不是所有条文都值得花额度重查。按用途分：

| 用途 | 复核范围 |
|---|---|
| **要写进文书、作为论证依据的条文** | 全部逐条复核，一条不漏 |
| 辅助性条文（背景、程序性引用） | 抽核；只要有一次对不上，这一批全部重核 |
| 检索员自己标了"不确定""前提不明"的 | 必须复核，这正是最容易错的地方 |
| 案例 | 案号必核；内容抽核 |

判断标准一句话：**这段话明天要交给法院或对方，就必须核。**

## 四、额度怎么算

一次完整检索的消耗大致是：

```
检索员：每个问题 1–3 次调用（精确工具 1 次，语义检索可能需要多轮）
主对话复核：每条关键条文 1 次
```

所以一条关键条文从查到用，**至少 2 次调用**。十个问题、二十条关键条文的检索，按 40 次左右估。

开查前先跟律师确认当日可用额度。额度和问题数不匹配时，优先保证：**要写进文书的条文 > 案例 > 背景条文**。

## 五、额度不够或 MCP 不可用时

按这个顺序降级，每一级都要在结果里注明：

1. **MCP 可用但额度不足** —— 只查要写进文书的条文，其余写"因额度限制未检索"，不猜。
2. **MCP 不可用**（服务故障、密钥失效）—— 改走官方法规库（flk.npc.gov.cn 等），结果注明"未经法宝核验，来源为官方数据库"。
3. **官方库也查不到，但有律师提供的文本** —— 用律师提供的文本，注明版本和来源。
4. **什么都没有** —— 写"未找到原文"，交给律师人工检索。**不得凭记忆补写条文。**

## 六、不一致怎么处理

复核发现不一致，按这个顺序：

1. **该条作废**，从结果里剔除，不修补、不"取两者中间的表述"。
2. 用工具重查一次，确认哪个是对的。
3. 重查仍不一致的，在结果末尾"存疑条目"里列出三个版本（检索员给的、复核取的、重查的），交律师判断，**不进正文**。
4. 同一份检索结果里出现**两条以上**不一致，整份作废，重新派检索员，并考虑换更强的模型。

## 七、回查记录怎么写

在检索文件末尾的"主对话回查"一节，逐条写，不要概括：

```
## 主对话回查

- 《民法典》第 577 条：已回查一致（法宝链接：…）
- 《民法典》第 584 条：已回查一致
- 京03民终1234号：案号已核，对应"某某公司与某某公司买卖合同纠纷二审民事判决书"
- 检索员所列《合同法》第 107 条：主体法已废止，应改引《民法典》第 577 条 → 该条作废
- 未回查：问题四的 2 条（额度用尽），正文已标注
```

最后一行永远写：**法条与案例均须律师最终核对，本回查只核对文本一致性，不构成法律意见。**

## 八、容易出错的地方

- **把旧法当新法**：检索员按训练记忆找到的是《合同法》，现行应为《民法典》。复核时看时效字段。
- **条号串位**：同一部法里相邻条文内容相近，条号抄错很常见。逐字比对能发现。
- **司法解释改名**：旧称"××规定"已改为"××解释"，或者旧解释被新解释吸收。看发文字号。
- **案例只核了案号没核内容**：案号真、但案由或裁判观点不是检索员说的那回事。裁决要点的原文要能对上。
- **把检索员的推断当条文**：检索员可能在原文后面加了一句解释，看起来像条文的一部分。摘录必须能在原文里逐字找到。
