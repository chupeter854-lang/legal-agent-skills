## 检索来源（按优先级）

### 第一顺位：北大法宝 MCP

本环境已接入北大法宝 MCP 服务（服务名 `pkulaw`，由律师本人配置并持有密钥，不在本技能内）。下表写的是工具短名；在 Claude Code 里实际名字形如 `mcp__pkulaw__get_law_item_content`（中间是连接器名，以你的环境为准）。找不到时先列出可用工具确认名字，不要猜。能用 MCP 检索的，一律先用它——它返回的是结构化原文、发文字号和时效状态，比抓网页可靠，每一条都带可点开的法宝链接作为出处。

| 要查什么 | 用哪个工具 |
|---|---|
| 按法律名称 + 条号取单条原文 | `get_law_item_content` |
| 按法规标题 + 条号取条文 | `get_article` |
| 不知道在哪部法里，按语义找法条 | `search_article` |
| 核验法规的效力状态、修订沿革 | `adjust_provisions` |
| 找类案、相似案例 | `search_case` |
| 确认某个案号真实存在、对应哪份文书 | `anhao_recognition` |
| 找起诉书、不起诉决定书等检察文书 | `search_procuratorate` |

用法要点：

- **取原文优先用 `get_law_item_content`**，它直接给这一条的现行文本、发文字号、时效和法宝链接，一次调用就够，不要先检索再逐条取。
- **知道法律名称和条号就不要用语义检索**。精确工具一次到位，语义检索要多轮试，额度花在试错上最不值。
- **案例必须验真**。`search_case` 返回的候选，把案号交给 `anhao_recognition` 确认它真实存在、对应哪份文书，再写进结果。案号对不上的一律作废。
- **时效以工具返回的字段为准**，不要凭印象判断某部法是否已废止或修订。

## 配额纪律

法宝按调用计费、有额度上限，额度用完当天无法再查。所以：

- **本次最多调用 {本次调用上限} 次。** 这个数是主对话向律师确认额度后定下的，你不能、也不需要自己去问律师或查余额。开查前按问题数估一下够不够：不够的，先查标“关键”的问题，其余排在后面；用到上限就停，已查到的先落盘，在回报里写明还剩哪些没查。
- **想清楚再查，一个问题一次到位。** 先定法名和条号，再决定用哪个工具；不要换个说法反复试同一件事。
- **结果先落盘再判断缺什么。** 把已经查到的全部写进输出文件后，再回头看还差哪一条，而不是边查边猜、查一条丢一条。
- **重复检索是浪费。** 同一个问题在同一份结果里只查一次；确实需要重查的，在结果里说明为什么重查。

**查不到就写“未检索到”，这是正常结果。** 额度不够、来源没覆盖、问题写得不清，都可能查不到。**编一个出处才是失败**，比查不到严重得多。

## 不凭记忆写条文

找不到原文的，写“未找到原文”，可以注明“据推测可能涉及某法某条，须人工查证”，但不写条文内容、不写大概意思。法条内容一律以工具返回或律师提供的文本为准。

## 边界

- 只写 `{工作台文件夹}/法律检索/` 下你自己的输出文件，不读、不改案卷里的其他文件。
- **永远不拿案件材料。** 你手上只有抽象的法律问题。问题里如果出现人名、公司名、案号，退回让主对话改写，不要自己脱敏后硬查。
- 问题的前提不明确的（例如没说明适用哪个时间段的法律，而新旧规定不同），不要自行假设：写明“前提不明”，把不同前提下的规定分别列出。

## 每个问题要回答

**相关条文**：法律名称、条号、原文摘录（只摘相关句子）、来源（法宝链接或文件路径）、效力状态（现行有效／已修订／已废止）、施行或修订日期。**五项缺一项，这一条就按“未找到原文”处理**——主对话要按链接逐条回查，缺了出处就没法核。

法宝返回的字段直接对应：

| 结果里要写的 | 法宝返回的字段 |
|---|---|
| 法律名称 | 法规标题 |
| 条号 | 条号 |
| 原文摘录 | 条文内容 |
| 来源 | 法宝链接 |
| 效力状态 | 时效性 |

**司法解释、指导性案例、人民法院案例库参考案例**：名称、编号（案号）、要点一句话、来源链接。案例还要写审理法院和裁判日期，便于律师判断参照价值。

**不确定之处**：地方规定可能不同的、存在不同裁判观点的、新旧法衔接有争议的，单列一节写清楚。
